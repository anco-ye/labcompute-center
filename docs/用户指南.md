# 用户指南

LabCompute · 科研算力中心

上传任务，等待计算，下载结果。平台自动安排主机、准备运行环境并交付输出；不再需要的任务随时取消。

## 账户与登录

平台地址：https://compute.example.org/ 。直接用浏览器打开，无需安装 Tailscale。

首次使用，请联系实验室管理员开通账户，再使用用户名和密码登录。

- 用户名：3–32 个字符，支持中文、字母、数字、下划线、点和短横线。
- 密码：非空即可，不限长度和复杂度。
- 同一浏览器会保持登录；有效期一年，使用时自动续期。主动退出或更换浏览器后重新登录。

每个账户都有独立的任务和结果列表。

## 准备任务包

先[下载 agent 准备材料](/static/agent-preparation-kit.zip)，将 ZIP 交给你的 agent。材料包含任务规范、带日期的运行环境快照和接入说明，agent 可离线阅读。请让 agent 按[任务包格式说明](/static/任务上传文档.md)，将程序、输入文件、依赖和任务清单打包为一个 ZIP。一个包可以包含多个计算单元，由平台安排并行和先后顺序。

可直接复制以下指令给 agent：

> 请解压我提供的 agent 准备材料，阅读任务上传文档和运行环境快照，按规范生成可上传的 ZIP 任务包，包含 manifest.json、程序、输入文件和依赖声明。将独立计算拆成可并行单元，注明步骤之间的依赖，并估计所需资源。只需静态核对和交付，不需要试跑、校准或持续在线。请告诉我任务包名称、计算内容和结果文件位置。
>
> 我的计算需求：〔填写目标、输入数据、计算方法和希望得到的结果〕

任务包最大 2 GiB。具体文件格式和资源字段由 agent 按上传规范准备。

## 上传任务

1. 在服务器资源下方、任务区域左侧点击“＋ 添加到队列”。
2. 选择 ZIP 任务包。
3. 点击“上传并开始排队”，等待上传完成。
4. 在“队列”或“进行中”查看任务。

**上传完成后可以关闭网页，计算会继续进行。** 再次打开平台即可查看最新进度。

若平台提示暂未开放计算，已上传任务保留在队列，开放后开始调度。

## 查看进度

| 状态 | 含义 |
| --- | --- |
| 排队中 | 等待合适的资源、运行环境或前序结果。 |
| 准备计算 | 正在准备输入和安装依赖。 |
| 运行中 | 正在计算，可查看进度和预计完成时间。 |
| 完成时间估算中 | 平台正在积累进度数据，随后更新预计时间。 |
| 回传结果 | 正在整理并保存输出。 |
| 已完成 | 结果已保存，可以下载。 |
| 正在取消／已取消 | 正在结束执行／取消已完成。 |
| 连接恢复中／同步恢复中 | 平台正在恢复主机连接并同步任务状态。 |
| 未完成 | 可查看已有输出和处理信息；输入或程序需要修正时，将提示交给提交 agent。 |

多单元任务可展开“计算明细与结果”查看各项进度。预计完成时间随实际计算进度更新。

整体进度按任务报告的样本数、循环次数或其他实际目标量显示。COMSOL等程序的求解阶段会单独显示阶段名称和比例；整体比例暂不可用时显示“计算中”和已用时间。多个目标分别展示，多单元批次显示已完成、运行和等待数量。

## 下载结果

在“已完成”中查看成功或报错的任务；已取消及归档任务可在“历史记录”中找到：

- 点击“下载结果”下载完整结果包。
- 多单元任务可点击“下载已有结果”整批下载，也可展开明细分别下载。
- 取消或未完成的任务，已有输出保存后会提供“下载已有输出”入口。

解压 ZIP 后查看程序输出，通常在工作目录的 `outputs/` 中；具体文件位置以提交 agent 的说明为准。结果包内的日志和运行记录也可以交给 agent 分析。

## 取消任务

在排队或执行中的任务卡片上点击“取消”，确认后等待状态变为“已取消”。平台会自动停止执行、清理进程，并保留已经完成的结果。

取消整个批次会结束其中尚未完成的计算。之后需要再次计算时，重新上传任务包即可。

## 查看主机资源

页面顶部每 5 秒更新一次资源信息。

| 指标 | 显示内容 |
| --- | --- |
| CPU | 型号、核心／线程数、整机占用率。 |
| 内存 | 当前已用容量与总容量。 |
| GPU | 显卡型号、占用率。 |
| 显存 | 当前已用容量与总容量。 |

资源卡片展示主机整体情况；自己的计算进度在任务卡片中查看。平台根据任务需求分配 CPU、内存、GPU 和运行环境。

## 问题与反馈

点击任务卡片的**状态标签**可以提交反馈，并在同一入口查看平台回复。

依赖准备、资源调度、符合条件的故障恢复、进程清理和结果回传由平台处理。任务输入或程序需要修正时，把提示和已有输出交给提交 agent，再上传修正后的任务包。
