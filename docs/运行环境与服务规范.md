# 算力中心运行环境与服务规范

更新：2026-10-15。

## 使用流程

用户按任务上传文档准备一个 ZIP，一个包对应一个批次。中心自动完成校验、排队、环境准备、执行、日志、用时估算和结果回传，不依赖 AI 或人工逐项派发。主界面只显示“运行中”和“队列”；上传过程属于队列，结束任务在历史记录查看。批次统一暂停、继续、取消，重试保留已完成项。

设计参考商用实例的“软件环境与数据分离”和批处理平台的“任务定义、资源申请与队列”结构，保留适合实验室的简单操作。

## Python 环境

- 控制服务：`C:/LabComputeCenter/venv`，只运行中心、agent 和监督进程。
- 基础模板：`runtimes/python311-v1`，环境 ID `python`。
- 科学计算模板：`runtimes/python311-science-v1`，环境 ID `python-science`。
- 每任务独立环境：`jobs/<id>/environment`。创建 venv 后安装模板锁定包，再安装项目 requirements，执行 `pip check`，保存实际 `pip freeze` 清单。
- 软件包轮子位于 `wheels`，下载缓存位于 `cache/pip`；复用下载包，不共享用户可修改的任务环境。
- 运行中发现缺少的 Python 模块时尝试安装并检查依赖，不重跑入口；无法安装或存在冲突时明确报错。系统程序和商业许可不属于自动补库范围。
- 环境准备有日志、取消和资源检查。失败保留原因及结果包；成功回传后清理可重建的任务环境，保留输入、工作输出和日志。

科学计算模板包含 NumPy、SciPy、pandas、matplotlib、h5py、scikit-learn、openpyxl。发布时记录完整依赖版本，并验证导入与线性代数计算。模板升级发布新修订，不在运行中的实验环境内安装。

MATLAB、COMSOL 按安装、版本、工具箱/模块及批处理许可发布。发现可执行文件但尚未完成批处理验证的环境显示待验证，调度器不会派发。GPU 环境须另行安装和验证，不列为现有节点能力。

## 资源和任务调度

任务包可声明 `resources.cpus / memory_gb / disk_gb`，普通使用者无需填写表单。Python 默认 1 CPU / 4 GiB；MATLAB、COMSOL 默认 4 CPU / 8 GiB。临时磁盘需求默认至少 4 GiB，并随输入包解压大小调整。

中心通过 SQLite 事务分配租约，结合节点心跳、运行环境、CPU、内存、临时磁盘及环境最大并发数领取任务。多个任务分配不重叠的 CPU 编号，保留系统 CPU 和内存余量；监督进程检查整个任务进程树的内存。磁盘需求用于准入预留，不是文件系统硬配额。

已交接的旧实验待运行单元由中心唯一派发，原有运行进程和结果保留。未交接的旧调度器由已登记的本机控制服务管理，不能重复派发。调度按提交顺序优先，在不推迟队首任务的条件下回填空闲资源。外部进程按实际 CPU 亲和性范围预留；无法确认限制时保守预留整池，不以瞬时 CPU 使用率推断可用容量。跨账号观测须匹配 PID、创建时间及有效期。

任务准备和执行由独立监督进程负责，SSH 断开不影响计算。agent 恢复后加载持久状态，对照 PID 和创建时间核验。仍存活则接回原监督进程；确已退出则清理已核验的遗留子进程、保留输出并报告失败，不重复执行入口。取消、暂停、继续通过后台控制同步传递，长时间下载或回传不阻塞控制。Windows 计划任务可能包含计算子进程，更新时必须等活动任务结束，不能假设停止计划任务只影响 agent。

预计耗时由同任务同节点历史实测与程序进度产生。首次无数据时显示学习用时；多任务队列不编造启动时刻。管理员最长运行时间默认 7 天，环境准备最长 30 分钟，与预计剩余时间分开处理。

## 磁盘与结果

- 任务工作区和 Python 环境位于 C 盘 SSD。
- Win1 结果副本归档到 `E:/LabComputeArchive`；Win2 到 `D:/LabComputeArchive`。
- 中心持久保存上传包、结果和 SQLite；归档失败进入持久重试队列，释放计算槽位，工作目录仍保留。
- 网络失败自动重试回传；包超过上限或校验失败则报告明确错误并释放槽位。修正原因后沿用原任务重新回传，不重跑计算；错误说明包与真正结果使用不同下载标签。
- 页面展示固定磁盘容量、空闲空间及介质；内部工作目录、环境路径和诊断信息不占用主界面。
- 结果包包含工作目录、日志、退出状态、资源峰值、环境清单和执行命令，不打包整个 venv。

每个任务仍解压独立输入副本。大型共享数据集、按用户配额和自动清理策略可在需要时增加，不影响现有单文件提交。

## 运维

`deploy/prepare_runtimes.ps1` 准备并验证模板；`deploy/publish_runtimes.py` 发布目录。部署前备份程序、配置及 SQLite。中心登记目标版本并暂停该节点的新派发；本机 `LabCompute-FinishUpdate` 等中心和本机活动任务均清空后重启 agent，新版本心跳匹配后自动恢复接单。禁止停止承载运行中计算的计划任务。

账户由实验室管理员开通，匿名注册已关闭。Python venv 仅用于依赖隔离；Windows 普通用户任务使用独立系统账户，Linux 普通用户新任务使用经过实测的 Bubblewrap 文件与进程命名空间，只暴露本任务目录及受控运行库。旧运行任务保留启动时环境。
